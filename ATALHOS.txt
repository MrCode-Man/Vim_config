ATALHOS DO NEOVIM
=================
Dentro do nvim, <leader>? mostra os do buffer atual.

<leader> = espaço

GERAL
-----
\               abrir/fechar o Neo-tree (árvore de arquivos)
<leader>?       mostrar os atalhos do buffer atual (which-key)
<F1>            desativado de propósito (não abre a ajuda)
-------------------------

JANELAS (lua/core/keymaps.lua)
<C-h>           focar na janela da esquerda
<C-j>           focar na janela de baixo
<C-k>           focar na janela de cima
<C-l>           focar na janela da direita
<leader>sh      dividir a tela para a esquerda
<leader>sj      dividir a tela para baixo
<leader>sk      dividir a tela para cima
<leader>sl      dividir a tela para a direita

------------------------------
EDIÇÃO (lua/core/keymaps.lua)
<A-j>           mover a linha (ou seleção) para baixo
<A-k>           mover a linha (ou seleção) para cima
<A-Down>        igual ao <A-j>
<A-Up>          igual ao <A-k>
  Funcionam em normal, insert e visual; reindenta sozinho.

<leader>tb      listar buffers

GIT  <leader>g  (lua/plugins/git.lua)
<leader>gp      pré-visualizar o bloco alterado
<leader>gs      stage do bloco (alterna)
<leader>gr      descartar a alteração do bloco
<leader>gS      stage do arquivo inteiro
<leader>gR      descartar o arquivo inteiro
<leader>gD      diff do arquivo com o índice
<leader>gb      quem alterou a linha (blame)
<leader>gl      alternar blame inline
<leader>gd      abrir Diffview (diff / conflitos)
<leader>gq      fechar Diffview
<leader>gh      histórico do arquivo atual
]c / [c         próxima / anterior alteração Git (em modo diff, vale o padrão do vim)

  Só dentro do Diffview (resolver conflitos):
  <leader>go    escolher nossa versão (ours)
  <leader>gt    escolher a versão recebida (theirs)
  <leader>ga    manter as duas versões

-------------------------------------------
MARKDOWN  <leader>m  (lua/plugins/markdown.lua, só em arquivos .md)
<leader>mv      modo visualização: renderiza títulos, listas, tabelas, código
<leader>me      modo edição: mostra o texto cru (só no buffer atual)
  Ao entrar no insert o texto cru aparece sozinho; ao sair, volta a renderizar.

-------------------------------------------
LSP  (só em buffers com servidor LSP ativo)
Sem leader:
gd              ir para a definição (Telescope: salta direto se for uma só)
K               documentação / tipo sob o cursor
[d / ]d         erro anterior / próximo erro

Importar (fora do <leader>l):
<leader>i       importar o que está faltando (cursor no erro; aplica direto ou lista as opções)

Com <leader>l:
<leader>la      ação rápida / quick fix
<leader>lu      usos da palavra (find usages)
<leader>li      ir para a implementação
<leader>lt      ir para a definição do tipo
<leader>ld      mostrar o erro/aviso da linha
<leader>lp      painel de problemas do projeto (Trouble)
<leader>lx      alternar modo "chato" de diagnostics
<leader>lr      renomear em tempo real (IncRename); depois troca também o que sobrar em
                comentários/strings/docs (calcular_total, calcularTotal... viram as variações
                do nome novo). Ocorrência em código de outro símbolo nunca é tocada.
<leader>ls      símbolos do arquivo
<leader>lS      buscar símbolo no projeto
<leader>lc      quem chama essa função
<leader>lC      o que essa função chama
<leader>lT      hierarquia: subtipos
<leader>lH      hierarquia: supertipos
<leader>lR      reiniciar os servidores LSP
<leader>lh      alternar hover automático
<leader>ln      executar code lens da linha (se o servidor suportar)
<leader>lf      formatar o código agora (normal e visual; funciona sem LSP)
<leader>lF      ligar/desligar o formatar ao salvar (começa ligado)

AUTOCOMPLETAR (nvim-cmp, modo insert)

COMENTÁRIOS COLORIDOS (lua/core/comentarios.lua, automático)
A linha inteira ganha fundo colorido (como o cursorline) e o texto do
marcador até o fim da linha fica na cor. Só vale se a palavra vier depois
de um marcador de comentário (# // -- /* * ")

azul      TODO       falta fazer, mas NÃO está quebrado (melhoria, caso não tratado)
amarelo   NOTE       explicação, não é tarefa (o porquê de algo não óbvio)
vermelho  FIXME      está ERRADO/quebrado e precisa de conserto
vermelho  BUG        bug conhecido (falha em tal situação), ainda sem correção
laranja   HACK       gambiarra: funciona, mas é feia ou frágil
laranja   XXX        olhar aqui, algo suspeito/perigoso (parecido com HACK/FIXME)
laranja   WARN       alerta a quem for mexer: mudar aqui quebra outra coisa,
laranja   WARNING    ou a ordem importa
roxo      PERF       ponto lento / que dá pra otimizar
roxo      OPTIMIZE   (igual a PERF)
verde     SAFETY     Rust: fica acima de um bloco `unsafe` e explica POR QUE é seguro

Diferenças que confundem:
  TODO vs FIXME   TODO = o que falta; FIXME = o que está errado
  FIXME vs BUG    FIXME = precisa de conserto; BUG = sei que falha em tal caso
  NOTE vs WARN    NOTE informa; WARN previne erro de quem for alterar
Dica: escreva junto o que fazer ou por quê; "# TODO" sozinho não ajuda.
Cores/palavras: tabela no topo do lua/core/comentarios.lua

HARPOON  (lua/plugins/harpoon.lua) - até 5 arquivos favoritos
<leader>a       marcar o arquivo atual
<leader>A       desmarcar o arquivo atual
<leader>e       abrir a lista (dentro dela: dd remove a linha, d/p reordena, Enter abre, q fecha)
<leader>1..5    ir direto para o arquivo 1..5
<C-Tab>         próximo arquivo da lista   (só em terminais que enviam Ctrl+Tab)
<C-S-Tab>       arquivo anterior da lista  (idem)
<C-p>           próximo arquivo da lista   (só em modo NORMAL; funciona em qualquer terminal)
<C-n>           arquivo anterior da lista  (idem)
